已从 DragonBones Pro 当前工程实际导出 DragonBones 5.5 JSON 和 PNG，并导入 Cocos Creator 3.8.8：

- Prefab：`assets/prefabs/bosses/CottonKingSimple.prefab`

- 已设置 `SHARED_CACHE` 共享动画缓存、`Enable Batch`，关闭骨骼调试显示。图集为透明 PNG，256 × 256；三个源资源合计约 29.4 KiB，不含引擎运行库。

将 Prefab 拖到游戏的 `UIRoot/Background` 下即可使用，与当前 2D 游戏层一致。动画保持原地播放，位置、伤害和召唤由游戏逻辑控制。选中根节点后，在 ArmatureDisplay 的 Animation 下拉框中切换动作。修改的是 Prefab 默认动作；运行时可以调用：

```ts
import { dragonBones } from 'cc';

const display = bossNode.getComponent(dragonBones.ArmatureDisplay)!;
display.playAnimation('idle', 0);   // 待机循环
display.playAnimation('charge', 1); // 蓄力一次
display.playAnimation('roll', 1);   // 翻滚一次
```

共享缓存用于本样例的简单独立动作；以后若需要动作混合，应重新评估缓存模式。播放接口见 [Cocos Creator 3.8 ArmatureDisplay 文档](https://docs.cocos.com/creator/3.8/api/en/class/dragonBones.ArmatureDisplay)。

## 重新导入动画包

1. 选择 **文件 → 导入数据到项目…**。
2. 数据路径选择同目录的 **CottonKing-DragonBones-import.zip**。
3. 选择 **导入到新建项目**，设置项目保存目录，然后导入。
4. 在动画列表中选择 `idle`、`summon`、`charge`、`roll` 或 `recover` 播放。
5. 导入完成后可在龙骨中保存为 `.dbproj`，继续编辑骨骼和关键帧。

如果 ZIP 没有自动识别贴图，可直接使用 `import/` 中的三个文件：

| 导入字段 | 文件 |
| --- | --- |
| 数据路径 | `cotton_king_ske.json` |
| 纹理集 | `cotton_king_tex.png` |
| 配置文件 | `cotton_king_tex.json` |

ZIP 是龙骨导入数据包，不是伪装扩展名的 `.dbproj`。三个文件需一起保留。

## 动作

| 名称 | 时长 | 表现 |
| --- | --- | --- |
| `idle` | 2 秒，循环 | 身体轻微呼吸、王冠摆动 |
| `enter` | 1.5 秒 | 落地压缩、回弹 |
| `summon` | 1 秒 | 抬高手臂、身体上提，再落下 |
| `walk` | 1 秒，循环 | 调整位置时的脚步和摇摆 |
| `charge` | 1.5 秒 | 身体压扁、蓄力抖动 |
| `roll` | 0.8 秒 | 收拢手脚、身体旋转一圈 |
| `recover` | 3 秒 | 停下喘气、王冠摇晃，恢复正常姿态 |
| `death` | 0.8 秒 | 弹起后压扁缩小消失 |

对应策划循环：`enter → summon → walk → charge → roll → recover`。`walk` 可循环两次，对应两秒调整位置。

全部动作原地播放，根节点不沿地图移动。召唤小怪、绘制路径预警、翻滚位移、伤害开关和奖励仍由游戏状态机实现；动画不会触发这些玩法副作用。`summon` 第 18 帧（0.6 秒）可作为将来召唤逻辑的表现对齐点。

运行库通过官方 npm 包 `@cocos/dragonbones-js` 获取，未打入交付包。导入包仅含原创贴图和动画数据。
